슬라이스 0(WY·NC·CA, 1,404명)을 **56개 관할구 10,446명**으로 넓혔다.

## 4. 측정이 찾아낸 것 — 3개 주로는 볼 수 없었던 6건

전량 측정의 값어치는 소요시간이 아니라 여기에 있었다. 여섯 건 중 **하나는 잡을 죽이고,
셋은 조용히 틀린 화면을 만든다.** 슬라이스 0에 하나도 나타나지 않는다.

### 4-A. 🔴 지역구 번호 20건이 CHECK를 위반한다 — 잡이 죽는다

`candidate.district`·`candidate_election.district`는 둘 다 `CHECK (0..60)`이다
(마이그레이션 0008은 `district.cd_number`만 넓혔다). 그런데 openFEC은 **61–92**를 찍는다:

```
CT-81 FL-81 GA-91 IN-90 MI-78 MI-87 MI-80 NM-66 NY-81 NY-88
OH-62 OH-65 OK-82 PA-64 SC-86(2) SC-89 TN-92 TX-66 UT-71
```

14개 주 20명. **CA·NC·WY에는 하나도 없다.** 전량은 첫 페이지 INSERT에서 실패했을 것이다.

**처리(결정: CHECK 유지, NULL + 집계)**: `fec.MAX_DISTRICT = 60`. 범위 밖 번호는 버리고 로그한다.
**의석 자체는 남긴다** — "이 사람이 이 주에서 이 해에 뛰었다"는 참이고,
의석을 통째로 버리면 그 해 로스터에서도 사라져서 2024 명부가 그에 대해 아무 말도 못 하게 된다.

CHECK를 넓히지 않은 이유: 92번 지역구가 존재한다고 스키마가 동의하게 되고,
앞으로의 오타 61–97까지 함께 통과시킨다.

`Candidate.districts_out_of_range`가 "openFEC이 아무 말도 안 함"과 "openFEC이 92라고 말함"을
구분한다. 후자만 세어 `dataset_sync_state.message`에 남긴다 — 맨 NULL로는 둘을 구분할 수 없다.

### 4-B. 실재하지 않는 지역구 140건 — 적재되지만 어느 페이지에도 안 뜬다

CHECK는 통과하나 119대에 없는 자리다. 두 부류가 섞여 있다:

- **소멸한 실재 지역구 13건** — OH-16(Anthony Gonzalez), PA-18(5건), CA-53, MI-14(Brenda Lawrence).
  2010년 지도에는 있었고 2022년 재구획으로 사라졌다. **정당한 데이터다.**
- **어느 지도에도 없는 번호** — ID-24(주 의석 2), KS-39, ME-58, CA-0.

**처리(결정: 적재하되 집계)**. 손실이 아니라 도달 불가다. 잡이 매 실행 집계한다:

> district pages reach 10,151 of 10,323 House candidacies; **140** name a district
> this Congress does not have, **32** carry no district at all

32 = openFEC이 애초에 지역구를 안 준 12건 + 4-A가 NULL로 만든 20건.

### 4-C·D. 🔴 DC·준주 상세 페이지가 후보를 0건 보여준다

같은 하나의 의석을 **세 소스가 세 가지로 번호 매긴다**:

| 소스 | 값 |
|---|---|
| Census / `district.cd_number` | **98** (센티널, 마이그레이션 0008) |
| FEC / openFEC | **00** — 단 북마리아나 후보 7명 중 **4명이 `01`**, 괌 후보 1명은 **아무것도 없음** |
| 우리 코드 | 0 |

`page.tsx`가 `stored.cdNumber`(=98)를 그대로 넘겼다. `98 = 0`은 거짓이고, `0 = 1`도 거짓이다.
실패는 조용하다 — 페이지는 200으로 뜨고 후보 목록만 빈다.

**처리(결정: 정규화)**. 번호를 맞추는 대신 **번호로 맞추기를 그만뒀다**:
`hasSingleHouseSeat()` — DC의 하원 의석은 하나뿐이므로, 주가 DC인 하원 후보는
세 소스 중 무엇이 무엇을 찍었든 **전원 그 자리에 뛴 것이다.**
어떤 정규화보다 강한 진술이고, 실제로 참인 쪽이다. 괌의 NULL 지역구 1명까지 함께 걷힌다.

`district.cd_number = 98`이 그 조건을 데이터에서 판정한다. at-large **주**(WY·AK·DE·ND·SD·VT)는
해당 없다 — 거기서는 0이 실재하는 번호이고 세 소스가 모두 0으로 일치한다.

⚠️ **같은 결함이 ETL 매처에도 있었다.** `COALESCE(t.district,0) = ce.district`가 북마리아나에서
`0 = 1`이 되어 **그 관할구의 유일한 의원(King-Hinds)이 미연결로 남았다.**
페이지와 매처가 같은 규칙을 읽도록 양쪽 다 고쳤다. 연결 4/6 → **5/6**.

### 4-E. 준주 "상원" 후보 13건 — 존재하지 않는 자리

DC 8 · AS 2 · PR 2 · VI 1. 그 관할구에 연방 상원 의석은 없다.

**처리(결정: 적재 + 게이트 + 집계)**. 실제 FEC 공시 행이므로 그대로 저장하고,
`lib/jurisdiction.ts`의 `senateSeats = 0`이 화면에서 막는다(실측: DC 페이지에 0건 노출).
지우지 않는다 — 숫자를 예쁘게 만들려고 공시를 삭제하는 것은 FC-1의 정반대다.

| `H2NY18103` | NY-18 승 | 레코드 없음 |
| `H2TX03290` | TX-03 승 | 레코드 없음 |

슬라이스 0의 CA 6건과 같은 부류 — **FEC의 두 시스템이 서로 다르게 말한다.**

|---|---:|---:|

미연결 하원 56명 중 **54명은 같은 자리에 같은 성의 FEC 후보가 있다** — 애칭/법적 이름 차이,

**임계값을 낮추지 않은 이유가 이번에 실물로 나왔다**: AZ-7 Adelita S. Grijalva의 자리에는
`GRIJALVA, RAUL M`이 있다. **다른 사람(그의 아버지)이다.** 성만 보는 규칙은 그를 연결한다.
매처는 거부했다.

- **Neon 118대 의원명부 구멍**(2c §12 발견 6) — 미해결. 전량에서는 매칭 손실이 더 커진다.
- **수기 큐 55건** — 하원 현직 54명 + 사모아 대표 1명. 전부 이름 형태 차이이며 추측하지 않는다.
- R2 결과 워크북 스냅샷 — 이번에도 `r2.not_configured`로 건너뜀. 자격증명 있는 실행에서 자동으로 채워진다.
- `--states`가 전국 경로와 관할구별 경로를 가르는 사실은 워크플로 주석에 반영돼 있지 않다.

## 11. Neon 적재 (2026-08-28, 같은 날 후속)

앱 런타임(Neon)에 전량을 적재했다. 로컬 `.env`는 `localhost:55432` 그대로 두고,
**그 호출에만** `DATABASE_URL`을 Neon direct(unpooled)로 줬다.

### 자격증명 — 1차 시도는 인증 거부

첫 `neon.env`는 형식이 전부 맞는데(BOM 없음·unpooled·URL 인코딩 불필요)
`password authentication failed for user 'neondb_owner'`로 떨어졌다.
셸 `sed` 추출과 python `re` 추출이 똑같이 120자를 냈고 `psycopg` 직접 연결도 같은 에러라
가공 단계는 배제됐다 — **비밀번호 값 자체가 그 롤과 맞지 않았다.**

이때 "`npg_`+12자는 Neon 생성 비번치고 짧으니 잘려 붙었을 것"이라고 추정했는데 **틀렸다.**
재발급받은 정상 URL도 비번은 같은 16자였다. 실제 차이는 쿼리스트링이었다
(120자 → 144자, `&channel_binding=require` 추가). 길이로 절단을 추정한 것은 근거가 약했다.

### Preflight (읽기전용)

| 항목 | 값 |
|---|---|
| 엔드포인트 | direct (`-pooler` 아님) |
| 서버 | PostgreSQL 18.6 / postgis 3.6 |
| 마이그레이션 | **0001–0008 전부 적용** (pending 없음) |
| `district` | 441 |
| `candidate` / `candidate_election` / `campaign_finance` | 1,404 / 1,713 / **1,989** |
| 119대 `term` | house 449 · senate 104 |
| 118대 house `term` | **416** (로컬 441 — 보류 결정된 알려진 구멍) |

### 적재

```
DATABASE_URL=<neon-unpooled> uv run civiclens-etl candidates
```

**15분 50초.** 로컬(7분 46초)의 두 배이고, 차이는 전부 결과 단계다 —
`_apply_results`가 결과 1건당 1 statement라 Neon 왕복이 지배한다.

| 구간 | 소요 |
|---|---|
| 명부 (106페이지) | 2분 46초 |
| 자금 (6그룹) | 3분 51초 |
| **2022 결과 2,828건** | **4분 41초** |
| **2024 명부 2,545건** | **4분 16초** |
| 매칭·history·집계 | 17초 |

예측(12분 내외)보다 4분 길었다. 다음에 이 구간을 줄이려면 `_apply_results`를 배치 INSERT로
바꿔야 하는데, 지금은 15분이 6시간 캡의 4%라 손대지 않는다.

### 검증 — 로컬 대조

| 테이블 | Neon | 로컬 | |
|---|---:|---:|---|
| `candidate` | **10,446** | 10,446 | ✅ |
| `candidate_election` | **12,350** | 12,350 | ✅ |
| `campaign_finance` | 13,980 | 13,982 | ⚠️ **−2** |

관할구 56개, 주별 후보 수 **전 항목 일치**(차이 0). cycle별 자금·당락도 2024 행수(−2)를 빼면 동일:

| cycle | 행 | receipts | 당락 | W | L | N |
|---|---:|---:|---:|---:|---:|---:|
| 2022 | 3,788 | 77.4% | 74.7% | **469** | 797 | 1,562 |
| 2024 | 5,495 | 76.1% | 46.3% | 0 | 0 | 2,545 |

**−2의 정체**: 로컬에만 있는 `H0WY01051:2024`·`H2WY01081:2024` 두 행이고,
**receipts도 election_result도 NULL인 빈 행**이다. provenance를 보면 두 행 모두
`field='election_result'`만 있고 시각이 **2026-08-27** — 2c의 결함 A(시트 이름 접미사 매칭)가
잘못 쓴 `N`을 retract가 NULL로 되돌린 잔재다. **retract는 값을 지우지만 자기가 만든 행은 남긴다.**

즉 Neon이 빠뜨린 게 아니라 **로컬에 잔재 2행이 남아 있는 것**이고, 이번 적재 이전부터
(preflight 시점에 이미 로컬 1,991 대 Neon 1,989로) 존재했다. 아무것도 주장하지 않는 빈 행이라
데이터 오류는 아니지만, 두 DB가 갈리는 지점이므로 기록해 둔다.
